# Offline dashboard snapshots

LineWatchTO preserves the most recent successful public dashboard for TTC and GO/UP independently. This extends the original June PWA policy: API transport remains network-only, while the application explicitly stores and labels historical public observations.

- Browser local storage holds a versioned, bounded snapshot for each network. Only backend dashboards marked fresh and available/degraded qualify. Source time strings remain unchanged; the envelope records when the browser downloaded it. Fixtures, failed requests and unavailable responses cannot replace it.
- The retained view is historical immediately on a failed refresh or loss of connectivity, and after two minutes without a successful dashboard verification. Normal-service labels become “Current status unknown”; previously reported disruptions and planned notices remain readable. Seven-day-old, future-dated, corrupt and incompatible stored snapshots are discarded. Browser storage failures leave in-memory reconnection handling usable.
- A static `/offline` route contains a public bootstrap with no account, cookie or token reads. Service-worker installation caches this HTML and its referenced application code/styles/fonts, both SVG maps, and a compact raster map set for both networks and all themes (about 3.8 MB). Assets already visited are also warmed after registration. Exact cached release textures win; compact textures cover offline theme/network changes.
- Only failed public dashboard navigation (including HTTP 5xx or an eight-second timeout) falls back to that bootstrap. Other routes use the minimal offline page. Actual dashboard HTML, authentication pages and API responses are not cached by the worker. Caches and registration are scoped to the frontend release build label. Activation remains controlled by the existing app-update workflow; failure to install a complete new shell preserves the old worker.
- Saved real observations take priority over demo fallback on reopening during a backend outage. An offline network without a saved observation shows a map and unknown status, with no demo incidents.
- Arrival countdowns, surface arrival estimates, train markers, and current account commute/station impact summaries are unavailable in snapshot mode. Account data is not persisted by this feature. Existing account/API error behavior remains responsible for online operations; no writes are queued offline.
- Complete, unfiltered service-notice reads also retain one public collection per network for seven days. Offline searches filter this downloaded collection locally and carry a saved-time warning. Partial/query responses do not replace the complete collection. This does not imply complete source coverage. Accessibility details, station details, operational trip changes and timetable datasets are not downloaded for offline reuse.
- Online and visibility events resume dashboard checks; only a valid fresh response clears historical mode. The open service-notice panel also refreshes on reconnect and every 30 seconds.

This is the web/PWA implementation. The separate Expo prototype retains its existing query-cache behavior. Offline availability requires one successful service-worker installation and browser storage retention; a first-ever offline visit cannot download the app.
