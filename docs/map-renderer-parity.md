# Map renderer parity: TTC and GO/UP

TTC (`InteractiveTtcMap.tsx`, with train markers in `TtcTrainMarkerLayer.tsx` and badge obstacles in `ttc-map-obstacles.ts`) and GO/UP (`InteractiveRegionalMap.tsx` with `app/regional-map-overlays.ts`) must look and behave the same over their SVG maps: same overlay vocabulary, same gesture handling, same stability. Most GO/UP-only flicker came from drawing the same overlays twice, so both maps now share one overlay layer, `components/map-overlays/` ([plan](refactor-plan/08-unified-map-overlays.md)).

**Line and station alerts are shared.** Both maps draw line alerts with the same React components: `MapLineAlertLayer` (tubes, glyph lanes, casings), `MapLineAlertSelection`, `MapLineAlertTargets`, `MapLineAlertHoverCopies` and `MapLineAlertHoverOutlines`; and station alerts with `MapStationAlertRings` (ring target, beacon, core), `MapStationDirectionGlyphs` and `MapStationAlertForeground` (selection flash, hover priority ring). All are sized by each map's `MapOverlayPlane.unit` (TTC 1; GO/UP 196 / 96). TTC renders them in its SVG planes. GO/UP builds the same model items from its authored SVG (`app/regional-line-alerts.ts`, `app/regional-station-alerts.ts`); it renders line alerts through React portals into the layers `prepareRegionalMapMarkup` injects, and station alerts in its React-owned top plane. Overlay CSS sizes multiply by `--map-overlay-unit`. Commute previews are shared too: `MapCommutePreviewRoute` (route and endpoint dots, under station artwork) and `MapCommuteEndpointFlashes` (green flashes above it), built by TTC inline and by GO/UP's `app/regional-commute-preview.ts`. Station-only planned advisories are station alerts on both maps, chosen by the same `plannedAdvisoryStationImpacts` rule. A change to overlay drawing therefore lands on both maps at once. GO/UP's `RegionalOverlaySession` keeps only badge placement, station selection, station-label hover and pulse sync, until phase 5 removes it.

## Baseline contract

1. **Overlay nodes live as long as their content.** Rebuild overlay DOM only when what it draws changes, and only for the alert that changed. A dashboard poll returns new arrays and fresh `updatedAt` stamps even when nothing changed, so compare drawn content, not object identity (`regionalOverlayContentSignature`). When content does change, keyed React rendering re-renders only the changed alerts; GO/UP's line and station alerts get this from the shared layer. GO/UP's remaining session-built overlays match it in `RegionalOverlaySession.update`: it builds every overlay fresh, then `keepUnchangedRegionalOverlays` keeps each mounted node whose as-built markup is unchanged and `placeRegionalOverlayChildren` moves only out-of-place nodes, since re-inserting a node restarts its animations. Selection and hover state applied in place does not count as a change. Anything that names an overlay (hover mask ids) must derive from the alert, not its position, or one new alert would change every other alert's markup.
2. **Presentation state never rebuilds overlays.** Reduced motion, page visibility, hover, selection, and gesture/zoom/camera flags are applied in place. A reduced-motion toggle or a brief visibility flip (fired on window `focus`/`pageshow`) must not delete overlay nodes. Hover is written to the DOM by the shared hover controller (rule 8); GO/UP's session applies motion and its planned-marker selection with `setMotionPaused` and `updateSelection`, never `update`.
3. **Alert overlays never move.** No alert overlay animates, on either map, on desktop or phone, at any number of alerts: glyphs rest along their lane (the shared `GlyphLane` in `map-overlays/GlyphLanes.tsx`), line alerts have no pulse, and station alerts draw a still core, beacon, and ring. One-way alerts show their direction through the glyphs' orientation. Selection feedback (the intro flash, then the breathing highlight) is the one animation an alert gets, and only while it is selected; both maps time the intro with `useMapSelectionIntro` (`map-overlays/selection-intro.ts`), keyed by `mapSelectionIntroKey`; `tests/map-motion-parity.test.mjs` guards this.
4. **Gestures use the same flags and timing.** Both maps set `data-map-gesture-active`, `data-map-zoom-active`, and camera-moving flags on the map root, and share the simplification rules in `styles/map/base-map.css`. A direct drag follows the pointer with no transform easing. Wheel zoom enters zoom mode once per gesture and commits 100 ms after the last tick. Properties that gesture mode simplifies (`filter`, `stroke-width`) must snap back on release, never transition. Animating a blur back repaints the whole map layer on every frame, even for invisible glows. When ending a gesture, both maps must fire no transitions.
5. **Hidden means not rendered.** Content that should not paint must stay out of the paint tree the way TTC's does. Hide authored source artwork with `visibility: hidden` on its children; never use `opacity: 0` on a container, because Chromium gives the invisible content its own GPU layers (about 55 for GO/UP's station-label source). Keep idle hover copies at `display: none` until hovered, as TTC renders a hover copy only for the hovered impact. On GO/UP, hidden copies and an `opacity: 0` label layer nearly doubled paint work and GPU layers.
6. **Remaining pulses share one clock.** The pulses that are left (a commute preview, a selected station) resynchronize to the shared pulse cycle after a build or a motion resume, not on every gesture.
7. **The alert chooser rides the camera, and is placed only at rest.** Each map's camera writer passes every stage transform and transition to its `MapChooserFollower` (`components/map-chooser-follow.ts`). The card's portal `transform` then moves with its badge in lockstep, with no layout or React work. Placement runs only once the camera has committed and settled: never during a drag, pinch, or camera flight, and on GO/UP only after the stage's ease has landed. A spot that is still valid is kept (`preferred` in `overlap-chooser-placement.ts`). A new spot is reached by a glide on the portal's separate `translate` property. A badge panned off screen keeps its card attached. Geographic view follows MapLibre `move` events and re-places on `moveend`. The keep-out observer ignores map stages and the chooser itself, so camera frames do not trigger keep-out scans.
8. **One alert hovered is raised; a group is outlined.** Both maps run one hover controller, `installMapHoverController` (`components/map-overlays/map-hover-controller.ts`). It finds the hovered alert from the mouse's position: a station alert's ring first, else a line alert, which stays hovered while the pointer crosses a station drawn on top of it. Keyboard focus on an alert target hovers it too, on fine-pointer devices. A press or wheel on the map ends the pointer hover. Hovering one alert, on the map or as a chooser row, raises that alert's hover copy above the others with its outline. Group previews (the open chooser with no row hovered, or a hovered or focused overlap badge) draw one outline around the union of the alerts (the shared `renderMapPreviewOutline`) and light their station rings, without raising any artwork, since several alerts cannot all be on top. Map and chooser hovers each own their raise, so ending one never clears the other. Hover is written straight to the DOM, so it shows before the next paint, and is reapplied when an alert's overlay remounts. The group outline stays visible during drags, without its glow. Masked outlines (group outlines and raised hover outlines) hide while the map changes scale (`data-map-zoom-active` or a camera flight) and return when it settles.
9. **Keyboard focus is never hidden.** A keyboard-focused map target under the sidebar, rail, or a sheet, or off screen, pans into view using the insets selection framing uses (each renderer's `readOccludedInsets`) and the shared `app/map-focus-reveal.ts`. Only `:focus-visible` focus inside the camera stage pans; chooser rows and pointer focus don't.
10. **Train markers move by one model.** Both backends send timed markers that use the same placement rules: at most 0.95 of the link while moving, 0.98 and `moving: false` when stopped at a station, and at least 0.12 once a train has left one. Both maps then advance them every second (`useAdvancedTrainMarkers`) and animate them along the track with the shared `train-markers.ts` motion. TTC's feed restates predictions as held countdowns that slide later with the clock, so its service keeps the earliest prediction for each train's next station (`GtfsRtSubwayTrainMarkerService`). GO/UP times each link from the trip's departure, else the timetable (`MetrolinxVehiclePositionClient`).
11. **Badge connectors cross only open space.** Both maps pass the same artwork to `overlapBadgeConnector`: station names (GO/UP also connection labels and line-name badges), every other overlap badge, station dots, and transit line strokes. The straight line never enters them, except right where it meets its own overlay. Its landing point moves along the overlay within `CONNECTOR_DETOUR_RATIO` of the shortest line, or the shortest plus `CONNECTOR_DETOUR_BADGE_HEIGHTS` badge heights. Badge placement passes the same check to `placeOverlapBadges` (`connector`): a spot whose line is blocked is passed over for the next clear spot, an aligned row is dropped if it leaves a member without a line, and each placed line is reserved so later badges keep off it. Only when no nearby spot has a clear line is a badge left without one. The end dot sits just outside the outline where the line actually crosses it, so a slanted line steps out by the half-width over the crossing angle. `BADGE_FEATURE_GAPS.alertOverlay` (28) leaves room for that dot plus a short line; the placement grid can eat at most half of its 10-unit clearance, so a badge at its closest spot is still well past the connector minimum length (12) and gets a line. Badges keep the wide `BADGE_FEATURE_GAPS.transitLine` gap only from unalerted track: both maps pass their line obstacles through `withoutAlertedStretches`, so a stretch under an alert overlay keeps the overlay's tighter `alertOverlay` gap and badges can tuck into the nooks beside it.
12. **Station alerts are one component.** `components/map-overlays/StationAlertOverlays.tsx` draws every station alert, of every kind, on both maps and on desktop and mobile, from the model in `station-alert-model.ts`: an idle ring that is also the alert's pointer and keyboard target, a shaded beacon, and a still core over the dot, then one direction arrow per alerted dot, then the selected alert's flash and each alert's hover priority ring. Colours are TTC's (`stationAlertColor`): a red core and gold ring for a suspension or speed zone, amber for a delay, blue for a planned advisory. `stationImpactBeaconSize` (`components/station-impact-beacon.ts`) sizes the beacon at 2.2 core radii, or smaller when a neighbouring station dot is closer; two alerted dots close together, such as Spadina's platforms or a GO/UP pair, each get a full circle of half the space between them. Each map's adapter sizes the anchors: TTC's core is 26 units (48 at large stations), its ring 38 (56); GO/UP takes TTC's ratios of each dot's own radius (core 26/32, ring 38/26 of the core, arrow badge 24/32), since its dots vary. GO/UP's pill-shaped hub (Union) is an anchor shape of the same component: its filled outline marks the alert, with an invisible target band around it and no ring or beacon. The rings sit above station targets on both maps (TTC's interaction plane, GO/UP's top plane), and the beacon, core, and ring stay visible while the map moves. Metrolinx alerts carry no direction field, so a GO/UP arrow appears only when the backend names a trip's destination ("Towards Union Station"); `station-impact-direction.ts` points it towards or away from Union from the alerted station's place on the line.
13. **Desktop chrome never covers itself.** Both maps share one toolbar, placed by `observeDesktopControlRail` (`app/desktop-sidebar-state.ts`): centered over the whole map, moved only to clear an open sidebar and the right-hand buttons, dropping its captions, then the right-hand captions, before taking a second row. The desktop legend keeps its designed size on large windows and shrinks on small ones (`styles/map/map-legends.css`). The default camera framing itself is unchanged. Regression coverage: `tests/desktop-control-rail-placement.test.mjs` and the small-laptop baselines in `tests/smoke/visual-baselines.spec.ts`.
14. **Line alerts are tubes over the line.** Alert rails are opaque and wider than the line they cover: TTC 96 units on its 80-unit lines, GO/UP 196 on its 175-unit corridors. Neither has an outline at rest; only hover and group previews draw one. TTC lines run edge to edge in places (Lines 1 and 2 at St George), so each line's alerts sit over a casing in the map's background colour, 2 units wider per side (scaled on GO/UP) with flat ends, under all of that line's tubes. It shows only as a thin gap where another line's tube or track meets the tube, never at the line's own segment joins. The shared layer draws the casing on both maps; GO/UP corridors rarely meet, so it seldom shows there.

## Working rules

- When you change overlay rendering or gesture handling in one map, make the matching change in the other map, or record why the networks differ.
- Verify a change in both modes: pan, release, hover, wheel zoom, toggle reduced motion, and let a refresh pass. Overlays must not blink or restart. TTC often has no active impacts, so compare against a TTC fixture or scenario that has overlays.
- Regression coverage: `tests/map-motion-parity.test.mjs` (glyphs rest along their lane), `tests/station-alert-model.test.mjs` (station-alert colours, arrows and reach), `tests/regional-map-overlays.test.mjs` (poll-only changes do not rebuild; a changed alert replaces only its own nodes), the "regional overlay reconciliation" case in `tests/smoke/dashboard.spec.ts` (dropping and restoring one GO/UP alert leaves the others mounted), the label-hiding and glow-transition assertions in `tests/map-raster-renderer.test.mjs` and `tests/regional-network.test.mjs`, and `tests/map-chooser-follow.test.mjs` plus the settled-camera cases in `tests/overlap-chooser-placement.test.mjs` (chooser follow and sticky placement).
- To compare the two renderers, count GPU layers (DevTools → Layers, or CDP `LayerTree`) and pan paint time on both maps. Give TTC overlays first, for example from the smoke API stub (`tests/smoke/api-stub.mjs`).

- The map shares Chrome's tile memory budget with the whole page. When it is exceeded, Chrome logs `tile memory limits exceeded` and drops tiles page-wide, so the map and sidebar flicker and tear.
- The GO/UP-only tearing after a pan came from camera easing during the drag. Each move eased the stage over 0.1s, so the stage stayed in a transform transition for the whole drag. The redraw when it settled after release overflowed that budget on GO/UP's heavier stage. Direct drags now set the stage transition to `none` in both maps (`startGestureInteraction`, regional `onPointerDown`). Reduced motion hid the bug because it already turns that easing off. Sidebar incident borders were ruled out; they keep a live canvas only while animating.
- The GO/UP-only flicker while zooming with the alert chooser open came from the chooser's group outline. It is two SVG masks around the previewed alerts, and at Union those alerts span whole corridors. Chromium re-rasters masked content at every new scale. At 2560 px wide that overflowed tile memory on every zoom step: about 1,000 `tile memory limits exceeded` warnings in a 5-second burst, against about 60 with the outline hidden. Shrinking the mask region did not help (about 570). TTC's outlines usually cover a short stretch. Masked outlines therefore hide in both maps while the map changes scale. The remaining tile overflow, shared by both maps, came from Chromium re-rastering every stage plane at each zoom step. On desktop the stage gets `will-change: transform` while the scale changes (zoom or camera flight), so Chromium scales the existing raster and re-rasters once when the zoom settles. With both changes, a fast 5-second zoom burst at 2560 px went from about 1,230 warnings to about 65 on GO/UP with the chooser open, and from about 58 to 45 on TTC, with no visible flicker. Mobile performance mode keeps the stage flat. GO/UP hover copies also show and hide without an opacity fade: a fading SVG element gets its own GPU layer sized in GO/UP's SVG units (17038 × 9033 versus TTC's 4500 × 2182).
- `npm --prefix frontend run test:map-zoom-memory` guards this on a real GPU. It spreads two overlapping GO/UP alerts across every corridor and fails above 400 warnings per burst (about 85-135 with the fixes, about 1,800 without). To find a new tile-memory cause, launch Chrome with `--enable-logging=stderr --remote-debugging-port=9222`, reproduce at the user's window size, and switch suspects off with injected CSS over CDP while counting `tile memory limits exceeded` lines per burst. Headless runs at 1440 px did not reproduce this.

## MapLibre System Map (tried and retired)

In October 2026 both System Maps briefly drew with MapLibre from raster tile pyramids, then returned to these SVG renderers: on phones MapLibre's pan and pinch felt worse than the SVG stage's compositor transforms, tiles softened then sharpened while zooming, and first loads were slower. Its reason for existing, desktop zoom flicker at 2560 px, was already fixed here (masked outlines hidden and `will-change` while scaling, above). Keeping both renderers would have doubled every overlay change. Map View still uses MapLibre.

## Known gaps

- GO/UP's `RegionalOverlaySession` still places overlap badges and applies station selection imperatively. Phase 5 of the [plan](refactor-plan/08-unified-map-overlays.md) removes it and derives badge clearances from the shared overlay sizes.
- Deferred: measure both maps on a low-end Android phone before any renderer change: tap responsiveness (INP), long tasks during a live-data refresh, and GPU layer count during a pinch. Mobile performance is acceptable today, so this waits until a change needs it.
